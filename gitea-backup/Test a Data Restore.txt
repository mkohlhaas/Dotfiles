To ensure your backups are reliable, it is highly recommended to run a test restore. Since you are using SQLite, a restore simply requires downloading the zip file from Filen, extracting it, and placing the gitea.db file and repository folders back into their proper directories.
Here is the safest step-by-step workflow to simulate or execute a full data recovery on your Arch Linux machine.
________________
Step 1: Download the Target Backup Archive
First, pull down the desired backup file from your Filen cloud drive using the filen-cli tool.
1. List the available files in your backup folder to find the timestamp you want:
filen list /Backups/Gitea/

2. Download the specific zip file to a temporary restore folder in your home directory:
mkdir ~/gitea-restore-test && cd ~/gitea-restore-test
filen download "/Backups/Gitea/gitea-dump-YYYYMMDD_HHMMSS.zip"

________________
Step 2: Extract the Dump Contents
The zip file generated by gitea dump contains everything your instance needs to run. Unzip it to inspect the structure:


unzip gitea-dump-YYYYMMDD_HHMMSS.zip

Once unzipped, you will see the core components of your instance:
   * gitea-db.sql: A complete, clean SQL dump text file of your SQLite database.
   * gitea-repo.zip: A compressed archive containing all of your Git repositories.
   * app.ini: Your Gitea configuration file.
________________
Step 3: Stop Gitea to Avoid Data Corruption
Before restoring files to a live instance, stop the Gitea service to prevent active read/write conflicts:


sudo systemctl stop gitea.service

________________
Step 4: Restore the SQLite Database
Gitea handles database recovery by feeding the gitea-db.sql text file back into a clean SQLite database file.
   1. Locate your live gitea.db file. On a standard Arch bare-metal installation, it is usually located at /var/lib/gitea/data/gitea.db (check your app.ini if you customized it).
   2. Move the old database away as a safety backup instead of deleting it outright:
sudo mv /var/lib/gitea/data/gitea.db /var/lib/gitea/data/gitea.db.bak

   3. Use the native sqlite3 tool to recreate the database from your backup file:
sudo -u git sqlite3 /var/lib/gitea/data/gitea.db < gitea-db.sql

________________
Step 5: Restore Repositories and Configurations
Next, restore your raw repositories and system files.
      1. Back up your current repositories directory just in case:
sudo mv /var/lib/gitea/data/gitea-repositories /var/lib/gitea/data/gitea-repositories.bak

      2. Unzip your backup repositories archive directly back into the Gitea data directory:
sudo -u git unzip gitea-repo.zip -d /var/lib/gitea/data/gitea-repositories

      3. (Optional) If you need to recover a broken configuration file, copy over the configuration file as well:
sudo cp app.ini /etc/gitea/app.ini
sudo chown git:git /etc/gitea/app.ini

________________
Step 6: Verify Permissions and Start Gitea
Before starting Gitea back up, verify that the files you just unpacked are owned by the git user so Gitea doesn't hit permission errors:


sudo chown -R git:git /var/lib/gitea/data/

Now, fire your Gitea instance back up:


sudo systemctl start gitea.service

Open your Gitea web interface in your browser. If your repositories look intact, your commit history is visible, and you can log in smoothly, your backup routine is officially verified and working!
________________
Step 7: Clean Up Your Temporary Restore Directory
Once you are confident the data is verified, you can delete the temporary test folder from your laptop to save space:


rm -rf ~/gitea-restore-test
